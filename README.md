# منصة اقرأ لإدارة المسابقات القرآنية

تطبيق ويب مستقل لجمعية اقرأ لعلوم القرآن، له تسجيل دخول خاص به، ويُنشر على Render عبر GitHub. هذا **التسليم الأول** وفق وثيقة المواصفات: **التسجيل المركزي والأهلية، والحسابات والصلاحيات، وفصل قسمي الرجال والنساء**.

## مساحات العمل والصلاحيات

لا يدخل أحد إلى بيانات المسابقة إلا بحساب. تُفحص الصلاحيات **على الخادم في كل طلب**، ولا يكفي إخفاء زر في الواجهة. إذا طلب أحدٌ سجلًّا خارج نطاقه، يجيب الخادم بأنه «غير موجود».

| الحساب | ماذا يرى | ماذا يفعل |
|---|---|---|
| **المتسابق** | ملفه ومشاركاته فقط | ينشئ حسابه برقم هويته، ثم يسجّل في الفروع المسموحة لفئته. يعدّل طلبه قبل المراجعة وضمن موعد التعديل، ويحدّث أرقام التواصل، وينسحب |
| **المحكم / منسق لجنة التحكيم** | ملفه وتكليفه | لا يطّلع على التسجيلات (التحكيم في التسليم القادم) |
| **رئيس لجنة التحكيم** | تسجيلات قسمه للاطلاع، دون الهوية والهواتف | لا يعدّل ولا يصدّر |
| **الإدارة التنفيذية** | تسجيلات قسمها فقط | القبول، وطلب الاستكمال، وعدم القبول، والتصحيح الإداري الموثق، وإعادة تعيين كلمة مرور المتسابق، والتصدير إلى Excel |
| **الإدارة العليا** | القسمان، مع التصفية بأحدهما | كل ما سبق، إضافة إلى إعداد الدورة والفئات والمقررات، وإدارة الحسابات، وسجل التدقيق، ونقل متسابق بين القسمين |

## ما يطبّقه هذا التسليم من الوثيقة

- **الفئة من سنة الميلاد تلقائيًا:** لا يختار المتسابق فئته. البراعم والناشئة يرون الحفظ وحده، وتُزال الفروع غير المتاحة عند تغيير السنة. يرفض الخادم السنوات غير الصالحة والحدود المتداخلة.
- **ملف شخص واحد، وتسجيل واحد في الدورة، ومشاركة مستقلة لكل فرع:** كل ذلك في معاملة واحدة، مع قيد فريد يمنع تكرار الهوية وتكرار الفرع.
- **الحفظ:** قسم واحد، إما مقرر الفئة أو أحد مسارات «لكل الأعمار». **التلاوة:** ترتيل أو تدوير بمقطع الفئة. **التفسير:** مقرر الفئة. **البحث القرآني:** للتعريف فقط.
- **نسخة الفئة والمقرر** تُحفظ مع كل مشاركة، فلا يغيّر تعديل الإعدادات لاحقًا التسجيلاتِ السابقة بصمت.
- **التحقق من البيانات:**
  - تُحوَّل الأرقام العربية والفارسية إلى صيغة موحدة.
  - تُحفظ الهوية والهاتف نصًّا، مع الأصفار في أولهما.
  - يُقبل في الهوية من 6 إلى 20 رقمًا، وفي الهاتف من 7 إلى 15 رقمًا.
- **التصحيح الإداري:** يعرض أولًا أثره على الفئة والمشاركات والمقررات، ثم يُطبَّق بسبب مكتوب. تُحفظ القيم السابقة، ويبقى المعرّف الداخلي ثابتًا.
- **الانسحاب وإلغاء الفروع** لا يحذفان السجل التاريخي.
- **سجل تدقيق للإضافة فقط:** محمي داخل قاعدة البيانات من التعديل والحذف.
- **دورة مستقلة لكل سنة:** تُنشأ الدورة الجديدة بنسخ إعدادات السابقة بحالة «مسودة». المواعيد غير المحددة تظهر «بانتظار الإعلان».
- **التصدير إلى CSV** يفتح في Excel، ومحمي من تفسير النصوص معادلاتٍ.

**الدورة المرجعية 2026** (الفروع والفئات وسنواتها والمقررات) تُنشأ تلقائيًا عند أول تشغيل من جداول الوثيقة، ثم تُعدَّل من «إعداد الدورة». هذه البيانات ليست ثوابت في الكود.

## النشر على Render عبر GitHub

1. **GitHub:** أنشئ مستودعًا **خاصًا** باسم `iqra-competition`، وارفع إليه محتويات هذا المجلد. تأكد أن `render.yaml` و`Dockerfile` في جذر المستودع.
2. **Render:** اختر **New ← Blueprint**، ثم المستودع `iqra-competition`. سيعرض الخدمة والقرص الدائم من `render.yaml`.
3. أدخل قيمة **ADMIN_PASSWORD**: كلمة مرور مؤقتة لحساب `admin`، من 8 أحرف على الأقل.
4. اضغط **Apply**. يستغرق البناء الأول 3 إلى 6 دقائق.
5. افتح رابط الخدمة، وادخل بحساب `admin` وكلمة المرور المؤقتة، ثم غيّرها.
6. من **الحسابات** أنشئ حسابات الإدارة التنفيذية ورؤساء التحكيم والمحكمين لكل قسم. تظهر كلمة مرور مؤقتة لكل حساب مرة واحدة؛ سلّمها لصاحبه.
7. من **إعداد الدورة** راجع المواعيد والفئات والمقررات وشروط الفروع، واجعل حالة الدورة «مفتوحة».

**التكلفة:** نحو 7$ للخدمة و1.25$ للقرص (5GB) شهريًا.

**التحديث:** أي تعديل يُرفع إلى المستودع يُنشر تلقائيًا دون المساس بالبيانات.

**النسخ الاحتياطي:** نسخة يومية من داخل التطبيق في `/var/data/backups`، تُحفظ منها آخر 30 نسخة. ويضاف إليها اللقطات اليومية التي يأخذها Render للقرص.

## التشغيل المحلي

```bash
npm install
cp .env.example .env        # ثم عدّل القيم
npm run create-admin -- admin "الإدارة العليا"   # يطبع كلمة مرور مؤقتة
npm start                   # http://localhost:3000
npm test                    # اختبارات القبول والصلاحيات (45 اختبارًا)
```

## النسخة التجريبية (داخل المتصفح)

مجلد `demo/` يبني ملف HTML واحدًا يشغّل كود الخادم نفسه (`server.js`) داخل المتصفح، مع قاعدة بيانات تجريبية وحسابات جاهزة لكل دور. يُستخدم للتجربة قبل النشر، ولا يُرفع إلى الخادم.

```bash
cd demo && npm install && npm run build   # الناتج demo/dist/index.html
```

## نسيان كلمة المرور

- **المتسابق:** تعيد الإدارة التنفيذية لقسمه تعيين كلمة مروره من ملف تسجيله، فتظهر كلمة مرور مؤقتة يغيّرها عند الدخول.
- **الموظفون والمحكمون:** تعيد الإدارة العليا التعيين من «الحسابات».
- لا تُرسل رسائل جوال أو بريد في هذا التسليم.

## قرارات معلّقة من الوثيقة لم يُفترض فيها شيء

- **D09:** ربط حسابات المتسابقين ببوابة الجمعية، وحسابات أولياء الأمور لعدة أبناء. حاليًا لكل متسابق حسابه برقم هويته.
- **D07:** المجموعات التنافسية لمسارات الحفظ لكل الأعمار.
- **D10:** المواعيد وقنوات الإشعار.
- **D11:** منع فائز الدورة السابقة.

## هيكل الملفات

```
server.js            الخادم والواجهات البرمجية والصلاحيات
lib/db.js            جداول قاعدة البيانات (SQLite)
lib/rules.js         التحقق والتطبيع والأهلية وحالة التسجيل
lib/seed.js          الدورة المرجعية 2026 ونسخ الدورات
lib/auth.js          الجلسات وكلمات المرور والحماية
public/              الواجهة (عربية، من اليمين إلى اليسار، متجاوبة)
scripts/test.js      اختبارات القبول
```

## التسليمات القادمة المقترحة

- **التشغيل الميداني:** اللجان، والحضور، والطوابير، ونداء التالي، وشاشة انتظار لكل قسم.
- **التحكيم:** الاستمارات المستقلة لكل محكم، ومصفوفة الآيات، والمسودة والإرسال.
- **النتائج:** النتائج والاعتماد والتأهل.
- **التفسير:** اختبار التفسير الإلكتروني.
